# Bright Evidence — OpenAI Plugin Submission

This document tracks the repository-backed parts of the public OpenAI Plugin submission for **Bright Evidence**, published by **Lana Design**.

Current official references:

- Plugin packaging: `https://developers.openai.com/plugins/build/plugins`
- Public submission: `https://developers.openai.com/plugins/deploy/submission`
- Plugin guidelines: `https://developers.openai.com/plugins/app-guidelines`

OpenAI's plugin format and submission flow can change. Re-check the official documentation before each public submission or version update.

## Submission shape

Use a **With MCP** submission that combines:

- Universal MCP URL: `https://video.lanadesign.tech/mcp`
- final uploaded skill bundle from `plugins/bright-evidence/skills/`
- listing metadata based on `plugins/bright-evidence/.codex-plugin/plugin.json`
- reviewer fixtures from `plugins/bright-evidence/submission/test-cases.json`

Do not submit an existing `plugin_asdk_app...` integration ID. Public submission provides the MCP URL directly and OpenAI scans the server as part of the draft/review process.

The repository intentionally does not commit `.app.json`: that file is only useful for mapping a locally registered ChatGPT developer-mode MCP connection whose technical ID is generated by ChatGPT.

## Publisher / access prerequisites

Before creating the public draft:

- use the OpenAI Platform organization that will own the plugin;
- ensure the submitter has **Apps Management: Write** permission (organization owners already have the required access according to current OpenAI documentation);
- complete business/developer verification for the publisher identity **Lana Design** in that same organization;
- verify that the identity displayed in the submission portal matches the public website, support, privacy, and terms pages.

Repository code does not prove any of these platform-side states.

## MCP tab

Use:

```text
URL type: Universal
MCP Server URL: https://video.lanadesign.tech/mcp
Authentication: none (current server behavior)
UI / CSP: no custom plugin UI in this version
```

Then choose **Scan Tools** and verify that OpenAI discovers exactly the intended read-only tool:

```text
normalize_evidence
```

Expected tool annotations from the server:

```text
readOnlyHint: true
destructiveHint: false
openWorldHint: false
```

The tool must continue to advertise its input and output schemas and must not gain browsing, persistence, model-calling, database, renderer, or write permissions without a separate reviewed change.

## Domain verification

When the OpenAI submission portal issues a domain verification token, put it in the deployment environment only:

```env
OPENAI_APPS_CHALLENGE_TOKEN=<exact token from OpenAI>
```

Do not commit the real token.

Redeploy the MCP service and verify:

```sh
curl -fsS https://video.lanadesign.tech/.well-known/openai-apps-challenge
```

The response body must equal the portal token exactly. The route returns `404` when `OPENAI_APPS_CHALLENGE_TOKEN` is unset.

The reverse proxy must forward all of these public paths to `http://127.0.0.1:4190` while preserving the original `Host` header:

```text
/mcp
/health
/plugin
/privacy
/terms
/support
/.well-known/openai-apps-challenge
```

Do not expose Docker port `4190` on a public host interface just to satisfy domain verification.

## Privacy / operations gate

Before clicking **Submit for Review**, verify the deployed environment matches the public policy:

- evidence request bodies and EvidenceBundle results are not persisted by the MCP application;
- application logs contain only request metadata and no claims, excerpts, full request bodies, authentication secrets, or raw query strings;
- reverse-proxy and hosting operational logs for this service are configured for retention of **no more than 30 days**;
- no analytics, ad, surveillance, or data-broker forwarding has been added outside this repository without updating the privacy policy and re-reviewing the feature.

The repository can enforce the first two application-level properties but cannot enforce an external proxy/hosting provider's log-retention setting. Capture operator evidence for the <=30-day setting before submission.

## Skills tab

Upload the final bundle from:

```text
plugins/bright-evidence/skills/
```

The bundled `public-evidence` skill is intentionally scoped to:

1. research through ChatGPT's approved public web capabilities or user-provided public URLs;
2. atomic claim extraction with provenance;
3. treating source content as untrusted data;
4. sending the complete candidate batch to `normalize_evidence` without pre-deduplication;
5. presenting normalized evidence, rejected items, and unresolved conflicts.

It must not become an instruction to scrape login-gated services, bypass access controls, collect restricted data, or invent evidence.

## Starter prompts

Use realistic prompts such as:

The initial set contains exactly:

- 3 negative cases

Each case is intended to be runnable without internal network access or private accounts. Re-run them against the deployed server and final skill snapshot before submission.

Suggested initial release notes:

> Initial Bright Evidence submission by Lana Design. The plugin combines a public read-only MCP tool (`normalize_evidence`) with a public-source research skill. ## Pre-submit verification

Run repository verification on the exact candidate head, then deploy and smoke-test the real HTTPS routes:

```sh
npm test
npm run lint
node --check mcp/server.mjs
node --check mcp/public-pages.mjs
docker compose -f compose.mcp.yml up -d --build

curl -fsS https://video.lanadesign.tech/health
curl -fsS https://video.lanadesign.tech/plugin >/dev/null
curl -fsS https://video.lanadesign.tech/privacy >/dev/null
curl -fsS https://video.lanadesign.tech/terms >/dev/null
curl -fsS https://video.lanadesign.tech/support >/dev/null
```

After the token is configured:

```sh
test "$(curl -fsS https://video.lanadesign.tech/.well-known/openai-apps-challenge)" = "$OPENAI_APPS_CHALLENGE_TOKEN"
```

Then in the OpenAI Platform submission draft:

- confirm Lana Design identity is verified;
- confirm Apps Management Write access;
- complete domain verification;
- Scan Tools and inspect `normalize_evidence` schemas/annotations;
- upload the final skill bundle;
- add starter prompts;
- enter the 5 positive + 3 negative tests;
- choose only countries/regions where legal/support operations are ready;
- review release notes and policy attestations;
- submit for review.

Submission starts OpenAI review; it does not publish immediately. Only publish after the submission is approved and the live acceptance checks still pass.
