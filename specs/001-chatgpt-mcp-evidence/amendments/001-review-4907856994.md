# Spec 001 Amendment — Review 4907856994

Status: accepted implementation clarification for PR #1.

This amendment resolves two ambiguities discovered during production-hardening review. It is part of Spec 001 for the current PR and supersedes conflicting wording in the original spec where stated below.

## A1 — Locale-ambiguous numeric separators

The normalizer has no locale/number-format input in v1. Therefore it must not choose between thousands-grouping and decimal interpretation when a single `.` or `,` is followed by exactly three digits and both interpretations are plausible.

Examples that remain textual without an explicit locale signal:

- `1,234`
- `1.234`
- `2,100K`

Unambiguous forms such as `2.1M`, `2,1M`, `12.5%`, and `12,5%` may still normalize deterministically. This clarification narrows the original “normalize only when confidently parseable” rule and supersedes any example/test that assumed a single three-digit separator was always English-style grouping.

## A2 — Numeric guards when `value` is omitted

`value` remains optional. Near-dedupe must also inspect deterministic numeric markers in the normalized claim text. If claim numbers materially disagree, the records must not near-merge. When exactly one non-date numeric claim value is unambiguously recoverable, it may be used for comparison/conflict detection without requiring the caller to populate `value`.

## A3 — Missing category

`category` remains optional. Missing category means unknown, not “not comparable.” Conflict detection may compare uncategorized evidence when metric/entity, unit, date, and value/negation guards establish a comparable fact. Unrelated uncategorized facts must remain separate.

## A4 — Source overflow supersedes original AC-7 wording for >20 sources

The original spec simultaneously limited `sources[]` to 20 and said all distinct canonical source URLs remain attached. For more than 20 sources those requirements cannot both hold.

The approved v1 overflow contract is:

1. dedupe preserves all distinct canonical sources internally before output selection;
2. output emits at most 20 sources per evidence record;
3. source selection is deterministic and prioritizes evidentially stronger provenance before stable canonical-URL ordering;
4. `omittedSourceCount` reports the exact number of additional distinct canonical sources not emitted;
5. `qualityScore` and `confidence` are computed only from the emitted source subset, so returned provenance fully explains those labels.

For 20 or fewer distinct sources, AC-7 remains unchanged: all distinct canonical source URLs remain attached. For more than 20, this amendment replaces AC-7 with the observable overflow contract above.

## A5 — Production dependency verification

The MCP production image is built from the authoritative frozen root lockfile in this PR. CI must run a native production advisory audit (`npm audit --omit=dev --audit-level=high`) against that lock graph. Any high/critical findings must be fixed or explicitly triaged before production readiness. A future MCP-only package/lock split is an optimization unless audit or runtime evidence requires it.
